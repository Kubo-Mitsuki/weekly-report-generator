## コミット1: スライドの見た目（.pptx と画面の面の両方）

1. **見出しの「先週」「今週」を、週の色の札にする。** 見本は次のとおり。
   - 札: 「先週」「今週」の2文字だけを、白の太字（20pt）で、週の色（`THEMES.last.accent` / `THEMES.this.accent`）で塗った四角の上に置く。四角は文字の左右に少し余白を持たせる
   - 続く文字: 札のすぐ右に「の目標とその進捗」を、18pt・細字・黒（`000000`）で続ける
   - 英語の行: 札の下の行に「Last week's goals and progress」などを、16pt・細字・灰（`333333`）で置く（札にしない）
   - 札は、テキストの強調表示（highlight）ではなく、塗った四角の図形（または塗りのあるテキストボックス）で作る。見出しの枠 `SLIDE_LABEL.box` の左上にそろえる
2. **「その他取り組むこと」の見出しを、目標の見出しと同じ文字の段にそろえる。** 日本語の行は18pt・細字・黒、英語の行は16pt・細字・灰（札は付けない）
3. **3色を、明るさと鮮やかさのそろった組に変える。** 今は今週の縞（`F4B183`）だけ彩度がずっと高く騒がしいうえ、青・橙・緑がばらばらに選ばれている。次の値にする（OKLCH で明るさと鮮やかさをそろえて計算した値。白い文字との比は 青6.5・橙3.5・緑6.0）

   | 用途 | 見出し・札 | 縞（濃） | 縞（淡） |
   |---|---|---|---|
   | 先週（青） | `2C6194` | `D4E1EF` | `EBF1F7` |
   | 今週（橙） | `C57539` | `F0DBCD` | `F8EEE8` |
   | その他（緑、2枚とも） | `3D6D48` | `D7E3D9` | `ECF2ED` |

   画面の面・タブの色も同じ値から作る（`layout.js` の値を使えば自然にそうなる）
4. **達成度に「%」を付ける。** 前後の空白を除いた値が半角の数字だけ（正規表現 `^\d+(\.\d+)?$`。例 `90`・`90.5`）のときは、スライドと画面の面に `90%` と出す。それ以外（`90%`・`約90`・空など）はそのまま出す。この変換は `slide.js` の1つの関数（例 `formatAchievement`）にし、スライドと画面の面の両方がそれを使う。保存するデータ（JSON・自動保存）は変えない（数字のまま）
5. テスト: 凍結版との比較テストは、`opts` で旧の値を与えれば今までどおり全ファイル一致するように直す。旧の値は「両週とも旧の青（`156082`・`D0DCE5`・`E8EEF2`）、その他も旧の緑（`196B24`・`D1DFD3`・`E8EFE9`）、見出しは1つのまとまりで18pt・灰・細字、札なし、その他の見出しも旧のまま」と「%を足さない」（例 `opts.percent: false`）。`opts` はテスト専用のまま。色と見出しを検査している既存のテスト（`test/render.test.mjs` など）の期待値は、この指示の値に改める

## コミット2: 入力画面の直し

1. **エラーと結果の表示を、押した場所の近くに出す。** 今は状態表示が画面の最下部にあり、画面の外に出る（高さ870pxの画面で y=941）。「出力」を押して入力エラーになっても見えない。
   - 状態表示を、上の操作の行（「出力」と「JSON」のボタンの横）に移す。スクロールしなくても見える位置にする
   - 入力エラーの文言は、`validate` の `message`（人の言葉）を出す。「入力エラー: name」のような内部の名前は出さない。問題が複数あれば最初の1件と「ほか N 件」
   - 入力エラーのときは、該当する欄へカーソルを移す。`name` → 苗字、`name_en` → ローマ字、`date` → 基準日。件数や形の問題（`last_week.goals` など）は対応する欄が無いので、カーソルは動かさない
   - JSONの読み込みを拒否したときも、同じ場所に理由（`message`）を出す
   - 役割の分け方: 上の状態表示は「押した操作の結果」（出力した・エラー・読み込んだ）。面の下の案内の行は「今の入力に残っている警告」（あふれ・目標が空の行・ありえない値）。警告は種類ごとに1行（セルごとに並べない）
   - CLI の文言は変えない（画面だけの直し）
2. **目標が空の行に、出力されないことを見せる。** 目標が空で、達成度か概要に何か入っている行は、出力とJSONから外れる（データの形はそのまま）。その行の目標のセルを赤枠にし、面の下の案内の行に「目標が空の行は出力されません」と出す。「出力」を押したときも、状態表示に同じことを添える（出力は止めない）
3. **在室時間と達成度のありえない値を赤枠にする。** 判定は、前後の空白を除き、達成度は末尾の `%` を1つ除いた値で行う。空は問題なし。値が `^\d+(\.\d+)?$` に合わない（`-1`・`abc`・全角数字など）、または範囲外（在室時間は 0〜24、達成度は 0〜100）なら赤枠にし、面の下の案内の行に1行出す。出力は止めない（警告だけ）。保存する値は変えない
4. **「出力」を上の操作の行に移し、画面でいちばん目立つボタンにする。** 目立つ（塗りの）ボタンは「出力」1つだけにし、「JSONを書き出す」「JSONを読み込む」は控えめな見た目にする
5. **上の操作の行の文字を13px以上にする**（ラベル・入力欄・ボタン）
6. **目標の引き継ぎのボタンの左右を入れ替える。** 左に「今週の目標を先週へコピー」（何も消さない）、右に「今週の目標を先週へ移動」（今週の欄を空にする）

## コミット3: 元に戻す・やり直す

- 画面の操作の行に「元に戻す」「やり直す」のボタンを置く。キーは Ctrl+Z（元に戻す）、Ctrl+Y と Ctrl+Shift+Z（やり直す）。Mac の Cmd も同じに扱う
- 戻せる対象は、画面の入力すべて: セルの文字、在室時間・達成度、氏名・学年・基準日・ファイル名の形式、目標の引き継ぎ（移動・コピー）、JSONの読み込み。表示言語の切り替えとタブの切り替えは対象にしない
- 履歴に積む「状態」は、週の `model`（空の行も含む4行ぶん、在室時間・その他も含む）と、面の上の欄（学年・苗字・名前・ローマ字・基準日・ファイル名の形式）をまとめた1つの写し。状態を取る関数と、状態を画面に戻す関数を1組作り、履歴はその写しを積む。表示言語は状態に入れない
- 1段の区切り:
  - 文字の入力（セル・面の上の欄）: 打つのが0.7秒止まったとき、または欄を離れたとき（1文字ごとに積まない）
  - 選択（学年・ファイル名の形式）: 変えたとき
  - スライダー: 動かし終えたとき（`change`）。動かしている途中の表示の更新は今のまま
  - 目標の引き継ぎ: 確認で取り消したときは積まない。実行したら1段
  - JSONの読み込み: 成功したときだけ1段。拒否したときは積まない
  - 直前と同じ状態は積まない。戻したあとに新しく編集したら、やり直しの履歴は捨てる。開いた直後（自動保存から戻した直後）の状態が出発点で、それより前には戻らない
- **キー**: `keydown` を document で（捕捉の段階で）受ける。IME の変換中（`isComposing`）は何もしない。**セルを編集している最中の Ctrl+Z も、ブラウザ標準のセル内の取り消しを止めて、この履歴で戻す**（2種類の取り消しを混ぜない）。その前に、打ちかけの文字があれば1段として確定させてから戻す
- 履歴は最大100段。ページを開き直すと消える（自動保存には入れない）。積んだとき・戻したとき・やり直したときに自動保存も更新する（今は欄の入力で自動保存しないので、ここで保存するようになる）
- 戻せるものが無いときは、ボタンを押せない見た目にする
- 足す文言（「元に戻す」「やり直す」、警告、エラーの「ほか N 件」など）は4言語ぶん入れる
