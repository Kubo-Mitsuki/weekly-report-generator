## 作業

### コミット1: 今週のスライドを見分けられるようにする（.pptx の変更）
1. **今週のスライドだけ、色を青から橙に変える。** 対象は、在室時間の表の見出しのセル（「Date」「在室時間」）、目標の表の見出し行、目標の表の縞。
   - 見出し: `C55A11`
   - 縞（濃）: `F4B183`
   - 縞（淡）: `FBE5D6`
   - 先週のスライドは今の青のまま。「その他」の表は2枚とも今の緑のまま
2. **目標の表の上の見出し**（「先週の目標とその進捗 / Last week's goals and progress」「今週の…」）を、2枚とも次のようにする。
   - 日本語の行: 26pt・太字・黒（`000000`）
   - 英語の行: 16pt・細字・今の灰色（`333333`）
   - 枠（x・y・w・h）は変えない。PowerPointで日本語の行が枠からはみ出すなら、日本語の行を24ptまで下げる
   - 「その他取り組むこと」の見出しは変えない
3. 色と文字の大きさはすべて `layout.js` に置く。週ごとに違う値は、週ごとの組 `THEMES.last` / `THEMES.this`（各 `{ accent, bandDark, bandLight }`。`accent` は在室時間の表の見出しと目標の表の見出しの両方に使う）として持つ。見出しの値は `HEADING`（日本語の行と英語の行それぞれの大きさ・太字・色）として持つ。見出しは日本語の行と英語の行を別々の文字のまとまり（run）にする
4. `buildSlide` の最後の引数に週の組を足す。`buildDeck(pptx, data, opts = {})` の `opts.themes` と `opts.heading` で、`layout.js` の値を差し替えられるようにする。**`opts` はテストのためだけのもので、CLI と画面からは渡さない**
5. テスト（凍結版との比較の改め）: `opts` に旧の値（両週とも青の組、見出しは1つのまとまりで18pt・灰・細字）を渡して描いたものが、凍結版 `legacy/old_slide.mjs` に新しい `weekDates` を渡したものと全ファイル一致することを確かめる。旧の見出しが1つのまとまりなので、`opts.heading` には「1つのまとまりで描く」形も選べるようにする。これで「変わったのは色と見出しだけ」と言える

### コミット2: 入力画面を「スライドの見た目そのもの」にする
**見本は `docs/mock_input_screen_20260929.html`**（2026-09-29に承認されたモック。データは架空。色の変数 `var(--…)` は別の表示部品のもので、単体では効かない）。考え方は次のとおり。

- 入力欄の並んだフォームをやめ、**スライドと同じ形の面**（左上の日付と氏名、在室時間の表、目標の表、その他の表）を画面に描く。その面のセルを押して、直接編集する
- 面の位置・大きさ・色は、`layout.js` の値から作る。**画面とスライドの見た目を、同じ定義から作る**ことが目的。今週の面は橙、先週の面は青になる
  - 縮尺: `s = 面の幅(px) ÷ 13.333`。位置と大きさは インチ × s、文字の大きさは pt ÷ 72 × s（px）
  - 書体は `'Yu Gothic', 'YuGothic', 'Meiryo', sans-serif`。セルの内側の余白は、pptxgenjs が表のセルに書き出す既定の余白と同じにする（pptxgenjs のコードか、生成した XML の `marL` などで確かめる）
  - 面に出す固定の文字（「目標」「在室時間」「先週の目標とその進捗」など）は、スライドと同じ `layout.js` の文字列をそのまま出す（画面の言語で変えない）
- 先週と今週は、今と同じくタブで切り替える。タブの色も、先週は青系、今週は橙系にする（今の今週タブの緑系をやめる）
- 「今週の目標を先週へ移動／コピー」と説明の「?」は、面の上の操作の行に1組だけ置く（タブごとに置かない）
- 文字のセル（目標・概要・その他）は、押すとその場で文字を入力できる（モックは下の欄で編集するが、セルの中で直接編集できればそれでよい。どちらにするかは任せる）
- 在室時間と達成度は、押すとスライダーで決める（在室時間 0〜12・1刻み、達成度 0〜100%・10刻み。今の刻みと同じ）。数字を直接打つこともできるようにする。直接打った値の扱い（丸めない・範囲外も文字のまま持つ・スライダー側だけ範囲に収める）は、今の `syncFromInput` と同じにする
- **文字が枠からあふれたセルは赤枠にする。** 判定は、画面の面に描いた文字の高さ（`scrollHeight`）がセルの内側の高さを超えたかで行う（モックの文字数での判定はやめる）。PowerPoint の描画とは少しずれてよい（目安の警告）。赤枠が1つでもあれば、面の下に「赤い枠は、文字が多くて枠から出ます」と1行出す
- データの形は変えない。目標が空の行は今の `collectData()` と同じく保存・出力から外れる（JSONの往復で空の行が詰まるのは、今と同じ動きとして受け入れる）
- 周りの画面は最小限にする。氏名・学年・基準日・ファイル名の形式・言語は、面の上の1〜2行に小さくまとめる

**今ある機能は全部残す**: 表示言語の切り替え（ja・zh・ko・en）、学年の選択、氏名（姓・名・ローマ字）、基準日（既定は次の火曜）、ファイル名の形式、「今週の目標を先週へ移動／コピー」とその説明、自動保存（`localStorage` のキー `pptx_gen_autosave` と保存する形は変えない。以前の保存を読めること。**基準日は今と同じく自動保存から戻さず、起動のたびに次の火曜にする**）、「出力」で .pptx を保存。画面の言語で切り替わる文言（面の外の文言）は、今の `T` の表を使い、足した文言も4言語ぶん入れる。

### コミット3: JSON の読み込み・書き出し
- 面の上に「JSONを書き出す」「JSONを読み込む」を置く
- 書き出し: `collectData()` の形（CLI の入力と同じ）を、`fileNameFor(data) + '.json'` で保存する
- 読み込み: ファイルを選ぶと、その内容で画面を埋める（基準日も入れる。`date` が無ければ今の基準日のまま）。読み込みは起動の初期化が終わったあとにしか起きないので、次の火曜で上書きされることはない
  - **拒否する**（画面を変えずに理由を状態表示に出す）: JSONとして読めない、全体がオブジェクトでない、`last_week`・`this_week` があるのにオブジェクトでない、`hours`・`goals`・`others` があるのに配列でない、件数の上限を超える
  - **読み込んでよい**: 氏名・ローマ字・日付が空や無いもの、`last_week`・`this_week` が無いもの（空の週として扱う）。入力の途中を渡すことがあるため。読み込みの判定は、`slide.js` に `validateImport(data)` として作り、出力のときの `validate` とは分ける
- `validate`（出力・CLI の判定）にも、上の「拒否する」の形の検査を足す（今は `last_week` が欠けたJSONを CLI に渡すと、描画中の例外になり「書き込みに失敗しました」と出る）。CLI のテストに、`last_week` が無いJSONで入力エラーとして終了コード1になることを足す
- README の「入力JSONの形」の節に、画面から書き出したJSONをそのまま CLI に渡せることを1行足す
